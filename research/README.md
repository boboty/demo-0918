# B1 · 真实新型储能资料池

## 这个目录是什么

回答的问题是：

> 现实世界里有哪些足够复杂的真实资料，可以用于验证我们的产品？

这是**研究暂存区**，不是产品数据资产。

## 这个目录不是什么

- **不是正式数据。** 不进入 `data/real/`，不产出结构化业务数据。
- **不是裁决结果。** 不对项目做最终状态判定、证据判定、冲突判定。
- **不是产品设计。** 不定义规则、不定义字段。

### 为什么不能直接进 `data/real/`

P02 规则尚未冻结，真实资料还没有经过：

实体对齐 → 证据判定 → 状态判定 → 冲突处理 → 同口径规则

在这些环节确定之前把真实资料写成正式业务数据，等于把**未经验证的研究猜测**
固化成产品资产。因此本轮止步于资料池。

## 研究范围

- **领域**：新型储能
- **对象**：龙源电力、三峡能源、中国电力三家新能源平台及其下属 SPV / 具体储能项目
- **下沉层级**：新能源平台 → SPV / 项目主体 → 具体储能项目

集团层信息可作为背景，但**项目事实尽量下沉到项目层**。
不为凑数量强行覆盖三家——**真实项目质量优先于企业分布均匀**。

## 来源优先级

| 层级 | 来源类型 | 用途 |
| --- | --- | --- |
| 第一优先 | 上市公司年报、交易所公告、政府备案/核准/批复、正式项目文件 | 可确认关键事实 |
| 第二优先 | 企业官网、政府官方网站新闻、招投标公告、官方项目动态 | 可确认多数事实，需注意口径 |
| 辅助 | 行业研究机构、权威媒体、行业数据库 | 交叉验证与背景 |
| 不作为核心 | 自媒体、聚合转载 | 仅可保留为线索，必须标注 |

## 真实性纪律

所有真实项目记录**必须有可访问来源**。严禁：

- 根据常识补数字
- 根据 MW/MWh 推投资额
- 推测未披露的经营结果
- 把新闻稿中的规划写成已建设
- 把"拟""计划""预计"改写为已发生
- 为了演示完整而编造真实公司数据

资料不足时明确写「**暂无公开可确认证据**」——这本身就是有效研究结果。

## 本轮只做资料采集，不做最终裁决

**这是本目录最重要的边界。**

可以记录：

- 来源原文摘录、URL、发布日期
- 企业 / 项目名称、原文中的 MW / MWh / 投资金额
- 原文声称的项目阶段、原文主体、所在地区、项目别名
- 可能的同一项目关系、可能的口径差异、值得后续核查的问题

**不可以决定**：

- 两个不同名称一定是同一个项目
- 项目最终当前状态是什么
- 两个不同数字哪个是正确值
- 哪条来源应该覆盖另一条
- 哪个项目已经满足 full_operation
- 哪个事实最终是 conflicting

允许的写法：「疑似同一项目，待规则判定」「存在口径差异可能」「需进一步确认」。

不允许的写法：「确认为同一项目」「该项目建设状态为已投运」。

## 两条硬性区分

### 1. MW 与 MWh 不能混成一个"项目规模"

功率（MW）与容量（MWh）是两个不同的物理量，必须分行记录，各自的原始表述都保留。

### 2. 投资金额必须保留原始口径表述

以下**不是同一件事**，不允许统一写成"投资金额"：

计划投资 / 协议投资 / 总投资 / 项目预算 / 资本开支 / 已转固资产

记录时保留原文措辞（例如"计划总投资约 X 亿元"），不做换算、不做推导。

## 使用方式

1. 先看 `candidate-projects.md` 了解候选项目全貌与疑点。
2. 需要核对某条事实时，用其中的 Source ID 到 `source-inventory.md` 查来源详情。
3. 需要机器处理时用对应的 `.json`。
4. 本资料池可**转换为 B2 的抽象验收场景**（见 `tests/acceptance-draft/README.md`），
   但不得把真实企业名与真实数字写进验收案例。
