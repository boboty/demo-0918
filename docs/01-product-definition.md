# 05方向｜衡策·新能源战略研究台
## 产品任务定义卡 V1.2 Final

### 1. 产品定位
面向集团战略规划与产业研究人员，融合公开情报、行业访谈、历史研究和集团内部项目资料，将分散信息还原为可核验的项目事实，在统一口径下比较同行布局、解释路径及形成原因，并结合集团自身条件形成可追溯、可持续复核的战略研判。

**核心价值：** 把一次性的战略研究，变成持续维护的事实、判断和证据体系。

---

### 2. 核心业务问题
1. **真实投入难还原**：签约、规划、备案、开工、并网、投产、盈利经常被混为一谈。
2. **同业数据难比较**：集团与平台、MW 与 MWh、计划投资与实际资本开支、独立储能与新能源配储均存在口径差异。
3. **历史判断快速过时**：新事实出现后，旧报告中的哪些判断仍成立、哪些需要复核，缺少持续维护机制。
4. **同行经验难直接迁移**：同行路径成立依赖自身条件，集团需要识别自身是否具备类似前提，以及需要补充哪些资源与能力。

---

### 3. 研究范围
- **背景研究层：** 风电、光伏。用于理解重点同行既有新能源布局与战略位置。
- **深度研究案例：** 新型储能。项目状态、投资口径、同业比较、路径分析、历史研判更新均围绕该案例做深。
- **研究对象：**
  - 集团层：观察战略方向、资源禀赋、重大投资动作。
  - 平台层：优先使用龙源电力、三峡能源、中国电力等真实公开数据做同口径比较。
  - 项目层：以具体储能项目作为事实原子。
  - 集团自身：使用明确标注的中国绿发 Mock 内部项目资料参与同口径比较和前提条件比对。

### 4. 数据策略
产品优先使用可核验的真实公开数据；对于演示链路所必需但公开数据无法获得的内容，使用 Mock 数据补足。

- 所有 Mock 数据均以**单条记录**为单位显式标注。
- Mock 数据不得与真实事实混合呈现。
- 不得将虚构的项目、经营数据或内部信息挂在真实企业名下。
- 对真实研究对象优先采用真实资料；若关键演示场景无法由公开资料支撑，则使用化名企业完成该部分演示。

---

### 5. MVP业务主链
**情报进入 → 事实还原 → 同口径比较 → 路径研究 → 集团对照 → 研判复核**

其中：

- **情报进入**：接收公开信息、内部项目资料、历史研究、访谈记录。
- **事实还原**：实体对齐、事实抽取、证据分级、项目状态判定。
- **同口径比较**：统一项目、规模、投资、时间等比较口径。
- **路径研究**：识别布局特征、形成原因和成立前提。
- **集团对照**：将同行路径前提与集团事实、资源条件逐项比较。
- **研判复核**：形成研判；新证据进入后识别受影响的历史判断，由研究员确认是否更新。

---

### 6. 三个关键演示点（WOW）

#### WOW 1：真实投入还原
采用“双轴”而不是金额漏斗。

**项目规模状态轴：**
规划 → 核准/备案 → 开工 → 首批并网 → 全容量投运

储能规模同时维护：
- MW：功率规模
- MWh：储能容量

**投资口径线：**
计划投资 / 协议金额 / 项目预算 / 已披露资本开支 / 已转固资产

缺少可靠证据时，正式输出“未知”或“暂无可确认证据”。

#### WOW 2：同行路径成立前提
不做主观评分，不输出“适配度 87 分”。

每种同行路径拆成若干成立前提，并与集团事实逐项比对：
- 满足
- 不满足
- 未知 / 需补充情报

每条前提必须标明来源：政策文件、同行披露、项目事实或“研究员假设”。

#### WOW 3：新证据触发历史研判复核
新情报进入后：
实体对齐 → 状态更新 → 同业比较变化 → 新事实与历史判断依赖发生冲突 → 历史判断标记“需要复核” → AI 提出新研判草案 → 研究员确认、修改或维持原判断。

AI 不自动改写正式研判。

---

### 7. 证据规则
| 级别 | 典型来源 | 使用原则 |
|---|---|---|
| A 强证据 | 年报、交易所公告、政府备案/批复、正式项目文件、经确认的集团内部台账 | 可确认关键事实和项目状态 |
| B 较强证据 | 企业官网、政府新闻、招投标公告、官方项目动态 | 可确认多数项目事实，需注意表述口径 |
| C 辅助证据 | 行业数据库、权威媒体、研究机构报告 | 用于交叉验证和补充背景 |
| D 线索证据 | 行业访谈、会议纪要、二手转述 | 用于发现线索、解释成因，不单独确认关键项目状态 |

**状态确认规则：**
- “全容量投运”等确定性关键状态需要 A 或 B 级证据支持。
- 仅有 C 级证据时最多标记为“待确认”。
- D 级证据不能单独推动项目状态变化。
- 来源冲突时维持原状态并进入人工复核，不由 AI 静默选择。

---

### 8. 历史研判最小结构
仅使用 **1 份 Mock 历史战略研究报告**，拆分出 5～8 条历史判断，不建设通用历史报告导入平台。

每条判断至少维护：

- 判断 ID
- 判断文本
- 依赖事实
- 依赖指标
- 成立前提
- 当前状态
- 证据版本
- 最近复核时间

新事实只根据明确依赖关系触发“可能受影响”的判断。

1. 情报收件箱
2. 项目事实台账
3. 同业比较

### 10. 商业可行性
**业务所有者与价值验收方：** 战略规划 / 产业发展 / 产业研究部门。  
**建设与维护方：** 数字化研发团队或对应技术团队。

持续价值来自持续变化的情报与持续复核的判断，而非一次性生成报告。

商业验证重点观察：
- 单条情报处理时间
- 需人工确认比例
- 一次专题更新所需人时
- 新情报到研判更新的周期

维护成本包括：
- 情报获取成本
- 模型调用成本
- 研究员复核人时

目标不是“无人化研究”，而是把研究员时间从资料搜集、重复核对和报告重写，转移到冲突判断、原因分析和战略研判。

---

### 11. MVP明确不做
- 不做全新能源行业知识库
- 不做实时全网爬虫
- 不做完整历史报告通用解析平台
- 不做储能收益预测模型
- 不做 GIS 选址
- 不做自动战略推荐
- 不做几十家企业覆盖
- 不做生产级权限、流程和数据治理

**本次只做深：**
新型储能 + 3 家重点同行平台 + 中国绿发 Mock 内部项目 + 1 份 Mock 历史报告。

---

### 12. MVP成功标准
用户能够围绕一个真实战略研究问题，通过多个关联业务界面完成一次完整研究：

1. 新情报能够被识别并对齐到正确项目；
2. 项目事实、规模状态和投资口径可追溯；
3. 同行和集团内部项目可以在统一口径下比较；
4. 路径、形成原因和成立前提均有证据或明确标记为研究假设；
5. 新事实影响历史判断时，系统能基于依赖关系触发复核；
6. AI 只提出研判草案，研究员保留最终确认权。
